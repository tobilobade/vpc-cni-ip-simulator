      How the simulator works

      • It pretends to be an EKS cluster using the Amazon VPC CNI (the aws-node pods). Nothing touches a real AWS account.
      • Each server (node) gets network cards (ENIs). Each card holds a fixed number of addresses, based on the real EC2 limits for that server type.
      • The CNI keeps spare addresses ready using WARM_ENI_TARGET (the default), WARM_IP_TARGET / MINIMUM_IP_TARGET, or with prefix delegation WARM_PREFIX_TARGET (blocks of 16).
      • Asking AWS for addresses takes about 5 seconds, and adding a network card about 15 seconds. A freed address rests for 30 seconds before it's reused.
      • Kubernetes puts pods on servers without checking addresses, so pods can get stuck in ContainerCreating. A new server needs one free address for itself, or it can't start.
      • Empty servers are removed after 10 minutes. Addresses are picked at random spots in the subnet, as on AWS, which is why prefix blocks can be hard to find.
      • Not included: custom networking / secondary CIDRs, security groups for pods, IPv6, Windows nodes, multiple subnets.
